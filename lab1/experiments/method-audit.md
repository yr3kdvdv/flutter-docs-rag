# Аудит методики этапа 06

Для независимой проверки методики использован только обезличенный протокол.

| Исполнитель | Выполнено |
|---|---|
| Подагент Codex `retrieval_method` | Сверил порядок фильтрации и бюджет. Проверил число фрагментов и отсутствие части эмбеддингов в локальном кэше. |
| Подагент Codex `metrics_review` | Пересчитал метрики трёх исторических черновых прогонов из raw. Проверил resume, знаменатели и API Langfuse. |
| Claude Code 2.1.331, `claude-opus-5-5` | Проверил равенство пула, отличие контекста от выдачи, ограничения малой выборки и смещение judge. |
| Google Antigravity CLI 1.5.16 | Провёл второй аудит протокола после отказа Gemini CLI 0.46.0 для индивидуального аккаунта. Antigravity вернул статус SUCCESS. Модель ответа в выводе этого вызова не указана. |

После аудита уточнены правила следующих сравнений. Уточнения сформулированы до
измерений rerank и генерации.

- Для проверки rerank оставляется запас кандидатов K=20. При выборе короткого
  пула на dev этот rerank-прогон рассматривается как отдельное сравнение на
  общем пуле. Влияние rerank оценивается только относительно off на том же
  индексе, с теми же K и порогом. Готовую конфигурацию с rerank выбирают по
  результатам фактически запущенного варианта.
- Эффект модели embeddings измеряется при одном section512. Тест других вариантов
  chunking проводился с Gemini. Выбор итоговой комбинации среди измеренных
  вариантов описывает рабочую конфигурацию. Взаимодействие chunking и модели
  embeddings остаётся открытым.
- Smoke Gemini включён в baseline как первые три уникальных вопроса.
  Защита resume фиксирует SHA кода, датасета, корпуса и промпта. Для сравнения
  используются 15 уникальных результатов. Записанные ошибки сохраняются отдельно.
- В слепую качественную сверку пойдут обезличенные варианты ответов с выдержками
  из источников. Judge Gemini используется одинаково для всех кандидатов.
  Оценки учётных метрик публикуются отдельно от независимой сверки.
- Порог оценивается на трёх dev без ответа. Один вопрос меняет оценку отказов
  на треть. При окончательном выборе отмечаются контекстные издержки и этот предел
  интерпретации. Section chunking сохраняет границы заголовков. Риск охватить
  сразу несколько gold-секций относится к стратегиям, которые пересекают границы.

## Слепая проверка ответов dev

Claude Code 2.1.331 (`claude-opus-5-5`) прочитал ответы и реконструкцию
контекста по семи вопросам. Имена модели и промпта заменены буквами до
проверки. После проверки раскрыто соответствие. A — Flash-Lite v2,
B — Flash-Lite v1.2, C — Gemma v1.2. Внешней модели переданы только вопросы
dev, эталоны, ответы и фрагменты публичной документации.

- `dev-005`: вариант B ответил на английский вопрос по-русски. Все варианты
  дали оба пути, но опустили схему HTTPS.
- `dev-006`: всем вариантам не хватило части примера с `CartModel` и
  `ChangeNotifierProvider`. Вариант A сузил решение до подъёма состояния.
  Вариант C неточно описал направление передачи callback.
- `dev-007`: все три команды действительны. У B и C использован shell-перенос.
- `dev-008`: вариант C добавил цитату, в которой указано лишь одно из
  приведённых в ответе значений COEP.
- `dev-009`: A и B дали верный идентификатор и импорт на русском для
  английского вопроса. У A также неточная локализация названия библиотеки.
- `dev-011` и `dev-013`: вывод Claude согласовался с эталоном, включая отказ
  при отсутствии сведений о HarmonyOS и AppGallery.

Все оценки на семи вопросах описательные. Смена языка может пройти
автоматический judge, а корректный синтаксис команды может не пройти
буквальную проверку кода.

## Сверка чисел Gemini

27 ноября 2026, Google Antigravity CLI 1.5.16 с явно выбранной моделью
`gemini-4-hydrogen-high`. Для восьми репрезентативных прогонов Gemini
получил только ID, признаки ответа и численные поля из каждой сырой
попытки. Тексты тестовых вопросов, ответы и выдержки не передавались.
[Вход численного аудита](evidence/stage06/numbers-audit-input.json)

Аудитор воспроизвёл Hit@5, micro Recall@5, правильные отказы, порог judge
и точность цитат там, где они применимы. Расхождений с агрегатами восьми
прогонов не обнаружил. В Gemma учтена одна неуспешная попытка и последующий
успех того же ID. Единственный набор строк с `split=test, final=true`
содержит 30 уникальных вопросов на SHA фиксации.

У поиска fixed с overlap и у секционного варианта с rerank одинаковый
Recall@5 на dev, но дополнительная найденная секция относится к разным
вопросам: `dev-004` и `dev-006` соответственно. Доля точных цитат
считается по ссылкам. Несколько ссылок на одну секцию считаются отдельно
и могут дать высокую точность при неполном покрытии ответа. На test
низкие оценки correctness получили `test-007`, `test-015` и `test-024`.
Численный аудит проверял агрегаты, а качество выбора, самих эталонов и
судьи ограничено методикой и размером выборки.
