# Этап 01 — подготовка среды, репозитория и команды

Ты Claude Code, основной исполнитель. Прочитай CLAUDE.md, AGENTS.md,
docs/PROJECT_BRIEF.md, docs/PROJECT_STATE.md, docs/source/README_PAD.md,
docs/BACKLOG.md, docs/RESEARCH_PLAN.md и docs/SKILLS_SPEC.md.

Подготовь проект к реализации лабораторной №1. На этом этапе не собирай весь RAG.

1. Проверь фактическую среду Mac и версии инструментов. Не считай, что данные
   предыдущей сессии всё ещё верны. Выбери поддерживаемый Python и зависимости;
   системный Python не заменяй. Создай воспроизводимую локальную среду проекта.
2. Создай docs/requirements.md: пункт задания, статус обязательности,
   запланированная реализация, ожидаемое evidence. Langfuse обязателен.
3. Создай docs/architecture.md: модули, потоки ingestion/query/evaluation,
   API-контракты, metadata, обработка ошибок, начальные решения и альтернативы.
   Фиксируй предположения. Это проектная архитектура, а не измеренные выводы.
4. Создай минимальную структуру lab1 и проверяемый development setup.
   README должен точно отличать готовые команды от ещё не реализованных.
5. Подготовь определения специализированных агентов и практичные skills
   по docs/SKILLS_SPEC.md, следуя текущей официальной документации клиента.
   Покажи, что клиент видит определения. Не запускай всех одновременно.
6. Проверь gh auth. Если вход есть, установи владельца, имя и видимость с учётом
   уже данных пользователем ответов. Если выбора ещё нет, задай один короткий
   вопрос с предлагаемым именем flutter-docs-rag. До ответа готовь всё локально.
   После явного разрешения создай remote, начальные Issues и шаблон PR/CI.
   Не подключай проект к существующему одноимённому repo без проверки.
7. Создай git-историю подготовки с осмысленным commit. Проверь состав файлов
   перед добавлением. Не публикуй секреты, данные чужих проектов или личные логи.
8. Подготовь .env.example без значений секретов и docs/SETUP_ACCOUNTS.md:
   куда перейти для Gemini API, Langfuse и Voyage, какие поля нужны и как их
   локально заполнить без передачи в чат. Проверяй текущие SDK/env names.
9. Сохрани docs/handoffs/latest.md и обнови PROJECT_STATE. Дай отчёт с реальными
   версиями, командами, результатами, Git SHA и URL, если они действительно есть.

Критерий: воспроизводимая подготовленная среда, матрица требований,
проектная архитектура, заготовленная команда, Git и понятные следующие действия.
Отсутствующий доступ к GitHub не мешает подготовке локальных файлов; явно отрази его.
Следующий этап — независимый аудит архитектуры по prompts/02-gemini-architecture.md.
