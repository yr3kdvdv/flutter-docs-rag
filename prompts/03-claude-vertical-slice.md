# Этап 03 — первый настоящий RAG + Langfuse

Прочитай AGENTS.md, docs/PROJECT_STATE.md, docs/architecture.md,
docs/requirements.md и docs/reviews/architecture.md. Если отчёт аудита передан
в сообщении, сначала сохрани его с указанием автора/инструмента и проверенного SHA.
Подтверждённые блокирующие замечания исправь; спорные разбери по доказательствам.

Создай небольшой сквозной сценарий с 5–10 автоматически загружаемыми
страницами Flutter: сбор -> clean/chunks -> embedding API -> Qdrant
-> query retrieval -> LLM API -> ответ с источниками -> trace Langfuse.
Это первый рабочий срез; расширенные эксперименты будут позже.

Используй реальные ключи только из локального окружения, не показывай их.
Если ключей нет, реализуй всё, что можно, и подготовь точную инструкцию ввода.
Тесты с mock отметь отдельно. Не выдавай mock за настоящий API smoke.
Проверь доступную модель маленьким запросом, затем зафиксируй её ID.

Реализуй таймауты, ограниченные повторы, обработку 429 и distinction:
«в корпусе нет ответа» отдельно от «внешний сервис недоступен».
Повторный ingest не должен дублировать документы. Сохрани metadata и snapshot.
Ответ должен ссылаться на реальные извлечённые источники.

Покажи один обычный запрос и один вне корпуса, trace/run identifiers,
реально запущенные проверки и команды для воспроизведения.
Проверь отправку trace после завершения короткого скрипта.
Оформи изменения по GitHub-процессу, если доступ уже настроен.

Готовность: пользователь может задать вопрос и открыть соответствующую
настоящую trace в Langfuse. Если часть не выполнена, явно сохрани BLOCKED
для этой проверки, а не объявляй весь этап пройденным.
Обнови handoff, состояние и объясни путь одного запроса простыми словами.
