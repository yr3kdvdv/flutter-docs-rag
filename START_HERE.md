# Пошаговый запуск Flutter Docs RAG

Подготовлено 23 октября 2026. Это стартовая папка будущего проекта, пока без приложения.
Все команды ниже выполняются в Terminal на Mac, кроме промптов для уже открытого чата.
Не запускайте все этапы одновременно. После каждого нужен проверяемый handoff.

## Вариант с координатором в текущем чате

Дайте текущему Codex-чату сообщение:

> Возьми координацию Flutter Docs RAG на себя. Работай в этой подготовленной папке.
> Выполни этап 01, делегируя реализацию настоящему Claude Code при доступном входе.
> Для независимого аудита используй Gemini через Antigravity, если это доступно.
> Сохраняй результаты в GitHub по этапам. При отсутствии доступа подготовь всё
> локально и назови одно конкретное действие, которое требуется от меня.
> Сам не подменяй Claude/Gemini субагентами Codex и не выдавай такую замену за аудит.

Укажите owner/name/visibility GitHub, если уже выбрали. Например, имя flutter-docs-rag;
видимость public подходит, если преподаватель должен открывать repo без приглашения.
Для private потребуется отдельно обеспечить доступ преподавателю.

ИИ может писать файлы, запускать инструменты, тесты и готовить GitHub-артефакты.
Входы через браузер, 2FA и секреты заполняет пользователь в соответствующих формах.
Запуск других клиентов из текущей среды зависит от доступной авторизации и разрешений;
установка бинарника сама по себе не подтверждает работоспособность вызовов.

## 1. Проверить входы

```bash
claude auth status
gh auth status
```

Если обычный Terminal тоже сообщает об отсутствии входа:

```bash
claude auth login --claudeai
gh auth login --hostname github.com --git-protocol https --web
```

В Claude выбрать аккаунт с Pro. В GitHub завершить browser/device login.
Не присылать в чат пароли, одноразовые коды или токены. Если Terminal показывает
успешный вход, не выполнять повторный login только из-за результатов среды Codex.
В Antigravity войти в Google-аккаунт с AI Pro, если клиент запросит вход.

## 2. Запустить Claude Code в папке проекта

```bash
cd ~/Documents/Codex/2026-10-23/4-github-education-benefits-2026-google/outputs/flutter-docs-rag
claude
```

В открывшийся Claude Code вставить:

> Прочитай CLAUDE.md, AGENTS.md и prompts/01-claude-bootstrap.md.
> Выполни этап 01. Входные материалы уже лежат в этой папке.
> Не переходи к реализации RAG до отчёта о подготовке и аудита архитектуры.
> Объясняй мне каждый результат как начинающему студенту.

Выход: требования, архитектура, среда, определения агентов/skills, GitHub-подготовка,
инструкции по ключам и docs/handoffs/latest.md. Входные файлы заново загружать не нужно.

## 3. Передать архитектуру Gemini / Antigravity

Во втором окне Terminal:

```bash
cd ~/Documents/Codex/2026-10-23/4-github-education-benefits-2026-google/outputs/flutter-docs-rag
agy --mode plan --prompt-interactive 'Прочитай AGENTS.md и prompts/02-gemini-architecture.md. Выполни аудит. Исходники не меняй. Верни полный отчёт в Markdown.'
```

В Antigravity проверьте, что для независимого аудита выбрана модель Gemini:
название клиента само по себе не определяет выбранную модель. Доступные модели
можно посмотреть командой `agy models` в обычном Terminal. Из среды этого помощника
этот запрос не выполнился: sandbox запретил создание локального служебного сервера.

Пока идёт аудит, Claude не должен менять проверяемые файлы. Режим plan возвращает
отчёт в разговор; сохранение файла не предполагается. Если автоматической передачи
между клиентами нет, скопируйте отчёт в разговор Claude вместе со следующим текстом:

> Это отчёт Gemini по архитектуре. Сохрани его в docs/reviews/architecture.md
> с указанием проверенного SHA. Разбери замечания и исправь подтверждённые проблемы.
> Объясни, какие замечания приняты, какие отклонены и на каком основании.

Если используется браузерный Gemini, прикрепите PROJECT_BRIEF, requirements,
architecture, RESEARCH_PLAN и handoff, затем отправьте текст prompts/02.
Локальные пути в браузерном чате сами по себе не открывают файлы.

## 4. Подготовить аккаунты API

Следуйте docs/SETUP_ACCOUNTS.md, который создаёт Claude на этапе 01.
Нужны Gemini API, проект Langfuse и позднее Voyage для сравнения embeddings/reranking.
Официальные точки входа: https://aistudio.google.com/ и https://langfuse.com/,
https://www.voyageai.com/. Формы и лимиты проверять в аккаунте.

Claude создаёт .env.example и объясняет локальное заполнение .env. Реальные значения
вводятся в локальный файл/форму, не в сообщения ИИ. Сначала достаточно ключей
для первого сквозного сценария; остальные подключаются перед сравнением моделей.

## 5. Создать первый рабочий сценарий

В существующей сессии Claude:

> Выполни prompts/03-claude-vertical-slice.md. Сначала проверь статус ключей
> без вывода значений. Покажи реальный ответ, источник и trace в Langfuse.
> Если что-то не удалось проверить, явно перечисли это в handoff.

При закрытой сессии сначала cd в папку проекта, затем `claude --continue`.
Если продолжение недоступно: `claude`, после чего попросите прочитать PROJECT_STATE
и latest handoff. Файлы позволяют восстановить состояние без полного старого чата.

## 6. Проверить результат через текущий Codex-чат

> Проверь проект в подготовленной папке по prompts/04-codex-verify.md.
> Используй отдельный worktree на текущем commit. Не меняй реализацию во время
> проверки. Верни подтверждённые дефекты, реальные проверки и непроверенные пункты.

Полученный отчёт передайте Claude:

> Исправь подтверждённые замечания review. Повтори затронутые проверки.
> Обнови handoff и GitHub. Не считай отсутствие доступа успешным тестом.

## 7. Построить полный pipeline

В Claude:

> Выполни prompts/05-claude-full-pipeline.md. Делегируй независимые части
> специализированным субагентам, максимум двум одновременно. Сначала согласуй
> контракты, затем используй разные worktrees. Обнови GitHub по задачам.

Готовность: полный pipeline, конфигурации вариантов, проверяемый dataset и runner.
Черновые вопросы должны пройти проверку перед использованием в оценке.

## 8. Выполнить исследование

В текущем ChatGPT/Codex-чате:

> Проверь готовность к prompts/06-research.md. Сформируй точное задание
> исполнителю, проверь эталоны и методику, затем координируй реальные эксперименты.
> Выбор параметров делай на development; final test оставь для финальной проверки.

Исполнителю Claude передаётся prompts/06-research.md и уточнённый план координатора.
Аудитору Gemini — dataset, методика, затем report/configs/raw results.

## 9. Финальный аудит и защита

В Antigravity (тот же проект, новый разговор при необходимости):

> Выполни prompts/07-gemini-final-audit.md. Проверь финальный commit,
> исследование и evidence. Не меняй исходники. Верни отчёт и список блокеров.

В Claude: сохранить отчёт, исправить подтверждённые замечания, повторить проверки.
В текущем чате:

> Выполни учебную часть prompts/08-release-defense.md. Проведи пробную защиту:
> задавай по одному вопросу, жди моего ответа, исправляй ошибки. Используй реальные
> результаты проекта, а не общие шаблонные ответы.

## Что считать завершением любого этапа

Не просто сообщение «готово», а файлы/commit, результаты фактически исполненных
проверок, список ограничений, обновлённый handoff и объяснение для студента.
Для API-сценариев — реальный ответ и trace, для исследования — raw results и configs.

## Если хотите использовать отдельный проект в ChatGPT

Это необязательно: текущий чат уже знает контекст. Для нового браузерного чата
прикрепите docs/source/README_PAD.md, docs/PROJECT_BRIEF.md, docs/RESEARCH_PLAN.md,
docs/PROJECT_STATE.md и отправьте текст prompts/00-chatgpt-coordinator.md.
После каждого этапа обновляйте переданный handoff: браузерный чат не видит автоматически
изменения файлов на Mac. При работе из текущего Codex-чата я могу читать их инструментами.
