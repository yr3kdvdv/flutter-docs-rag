## Подробно

### B1 — батчинг embeddings
- **Проверено:** `google-genai` 2.33.0 `embed_content(contents=...)` принимает список и вызывает
  `batchEmbedContents` (`google/genai/models.py:4900`). Батчинг технически доступен.
- **Не подтверждено:** «1500 RPD, 15–30 RPM» — страница rate-limits лимитов не публикует и отсылает к
  AI Studio. Неизвестно, считается ли батч одним запросом или по числу текстов.
- **Уточнение к формулировке:** ревизия 1 не предписывала «по одному chunk на запрос»; она умалчивала
  о батчинге. Это пробел спецификации, который мог бы привести к описанной проблеме.
- **Исправление:** `batch_size: 50`, `max_rpm` в конфиге; ограничитель RPM; возобновляемый ingest
  с кэшем (A-7 в architecture.md). Реальную квоту пользователь смотрит в AI Studio до этапа 03.

### B2 — блокировка embedded Qdrant
- **Проверено экспериментом:** процесс A открыл `QdrantClient(path=…)`, процесс B получил
  `RuntimeError: Storage folder … is already accessed by another instance`. В исходниках
  `qdrant_client/local/qdrant_local.py:167–174` используется `portalocker` на файле `.lock`.
- **Не подтверждено:** «риск повреждения хранилища при некорректном завершении» — не проверялось.
- **Исправление:** D3 — один процесс на хранилище, `serve --workers 1`; понятное сообщение об ошибке
  и `QDRANT_URL` как выход; строка в таблице ошибок §5.

### B3 — служебные `_*.md`
- **Проверено:** в `sites/docs/src/content` 11 файлов `_*.md`;
  `https://docs.flutter.dev/add-to-app/android/_initial-route-cached-engine` → 404, обычные страницы → 200.
- **Уточнение:** маска `**/_includes/**` избыточна — наш include был только `content/**`,
  а `_includes/` лежит рядом, вне `content/`. Фрагменты из него подставляются при обработке `{% render %}`.
- **Дополнительная находка исполнителя:** архитектура ошибочно называла тег `{% include %}`; в корпусе
  используется `{% render %}` (249 раз). Также 11 страниц с `noindex: true` и 21 с `sitemap: false`
  (внутренние страницы контрибьюторов) — исключаются из индекса.
- **Исправление:** exclude в base.yaml, `skip_front_matter`, §1 architecture.md. Итог: 638 индексируемых страниц.

### H1 — контекст страницы
Принято без проверки на данных: это стандартный приём, стоимость — несколько токенов на chunk.
Добавлено поле `embed_text`; эффект измеряется в экспериментах chunking, а не принимается на веру.

### H2 — дедупликация
Подтверждено чтением спецификации: правило «dedupe по document_id+section» действительно выбросило бы
второй chunk длинной секции. Исправлено: дубли только по `content_hash` и почти-дубли от overlap.

### H3 — `min_score: null`
Верно: cosine-поиск всегда возвращает top_k. Описаны два режима (отказ только моделью до калибровки;
порог на dev для каждой embedding-модели после). Отказ модели — структурным полем, не по тексту.

### H4 — длинные блоки кода
- **Проверено на снапшоте** (оценка токенов = символы/4): 3220 блоков, медиана 47, p90 212, p99 732,
  51 блок > 512, 16 > 1024, максимум ≈ 8500.
- Предложенного аудитором soft cap 1024 **недостаточно**. Принято: до 1024 блок не режется; длиннее —
  режется по пустым строкам, каждый кусок заново открывает ```` ```lang ````, флаг `code_split`.

### H5 — загрузка файлов
- **Проверено:** все 761 `.md` из `sites/docs/src` скачаны с raw.githubusercontent.com за 36 с при
  8 параллельных загрузках, 0 ошибок. Повторные запуски скачивают только изменённые файлы (diff по blob SHA).
- Принят пул с ограниченной конкурентностью и повторами. Tarball как основной путь **отклонён**:
  суммарный размер файлов snapshot — 2334 МБ (сумма blob size из Git Trees API; сжатый размер архива
  сервер не сообщил), а нужно 18 МБ Markdown; кроме того, архив не даёт инкрементальной загрузки.
  Остаётся запасным вариантом.

### 2.1 — Langfuse на ingest
Ревизия 1 не предлагала span на chunk, но гранулярность не была указана. Проверено: Hobby —
50k units/мес, единица — trace, observation или score. Уточнено: одна trace на запуск ingest
с агрегированными span; бюджет — в D8.

### 2.3 — вкладки
Проверено: `<Tabs>` на 36 из 697 страниц («активно» — преувеличение, но риск склейки языков реален).
`<Tab name="X">` превращается в подзаголовок «X:» перед своим кодом.

### M1 — flush Langfuse
**Отклонено как дефект:** D8 ревизии 1 уже предписывал `flush()` в конце CLI, а команд с Langfuse
пока нет — `cli.py` ничего не отправляет. Утверждение «интерпретатор завершит потоки до отправки» для
обычного выхода неточно: SDK v5 регистрирует `atexit.register(self.shutdown)`
(`langfuse/_client/resource_manager.py:278`). Уточнено: явный `flush()` в `finally` — защита и
понятность; `atexit` не сработает при `os._exit`/SIGKILL.

### M2–M4, L1–L3
- M2: промпты — файлы в `lab1/prompts/`; в trace — версия и sha256.
- M3: `EmbeddingTask = Literal["document","query"]`, адаптеры переводят в аргументы SDK.
- M4: проверка ключей для каждой команды до начала работы, exit 2 с подсказкой. Код появится вместе
  с командами `ask`/`ingest`/`serve` на этапе 03 (сейчас они не реализованы).
- L1: `fastembed` 0.9.0 существует, зависит от onnxruntime, не от torch (проверено на PyPI). Работа на M4
  и качество не проверены — это кандидат на embedding #2, решение после ответа преподавателя.
- L2: chunks одного документа группируются и идут по ordinal.
- L3: добавлено в RESEARCH_PLAN вместе с замечанием о дисперсии 15 dev-вопросов.

## Неточности в отчёте аудитора (для честности записи)
- §4 упоминает `gemini-2.5-flash` как наш model ID — мы его не предлагали; LLM в архитектуре не выбрана
  (`model: null`), а официальный список моделей помечает `gemini-2.5-flash` как не рекомендуемую для новых проектов.
- «~761 документ» — это вместе с `_includes`; в `content/` — 708, индексируемых — 638.
- Цифры квот Gemini (B1) и «повреждение хранилища» (B2) не подтверждены источниками.
