## 1. Резюме аудита (Executive Summary)

Архитектурный фундамент этапа 01 (docs/architecture.md, docs/requirements.md, lab1/) спроектирован на высоком
инженерном уровне:

- Чёткое следование принципам воспроизводимости (Python 3.12, uv.lock, src-layout src/flutter_rag/, исключение
  секретов через SecretStr).
- Грамотное разделение слоёв через абстракции Protocol.
- Честный подход к статусам реализации (cli.py возвращает код 2, нет имитации тестов).
- Соблюдено обязательное требование преподавателя по трассировке в Langfuse Cloud.

Вместе с тем выявлено 3 блокирующих архитектурных дефекта (Blockers) и 5 критических рисков реализации (High),
которые неизбежно приведут к сбоям на этапе 03 (вертикальный срез) и этапе 04 (grabber/ingest), если не будут
скорректированы в спецификации до написания рабочего кода.

## 2. Анализ предложенной архитектуры по контрольным направлениям

### 2.1 Покрытие требований лабораторной №1 и обязательного Langfuse

- Покрытие матрицы требований: Базовый pipeline (grabber → preprocessing → embeddings → vectorstore → retrieval →
  reranking → filtering → generation → observability) полностью сопоставлен с пунктами задания §2–§17
  docs/source/README_PAD.md.
- Langfuse: Использование Cloud EU Hobby, разделение спанов на каждый этап и фиксация версий промптов соответствуют
  требованию преподавателя.
- Риск телеметрии Ingest: Проект предполагает отправку трейсов при ingest. При объёме ~760 страниц и ~3000 чанков
  отправка спана на каждый чанк может исчерпать лимиты Langfuse Cloud Hobby или переполнить очередь памяти без
  батчинга.

### 2.2 Реальность автоматического grabber и повторных запусков

- Проверена структура репозитория flutter/website (commit 3eb87869bb0d): дерево Git Trees возвращает "truncated":
  false, что подтверждает возможность получения snapshot за один запрос.
- Критический дефект URL/Partials: Обнаружено, что в директории sites/docs/src/content/ находятся вспомогательные
  фрагменты (начинающиеся с _, например, _initial-route-cached-engine.md) и директория _includes/. Прямой запрос к
  https://docs.flutter.dev/add-to-app/android/_initial-route-cached-engine возвращает HTTP 404. Попытка генерировать
  такие ссылки нарушит требование к валидности источников (§13).
- Сетевая надёжность скачивания: Загрузка 760 файлов отдельными запросами к raw.githubusercontent.com займёт
  значительное время и несёт риск отсечки по IP. Необходимо использовать tarball-архив либо пул соединений httpx с
  ограничением конкурентности.

### 2.3 Сохранение provenance и кода из документации Flutter

- Документация Flutter активно использует кастомные JSX/MDX-теги табов: `<Tabs key="...">`, `<Tab name="Kotlin">` … блок ` ```kotlin ` … `</Tab><Tab name="Java">` … блок ` ```java ` … `</Tab></Tabs>`.
- Нативная зачистка HTML без учёта табов приведёт к склеиванию примеров на разных языках программирования или
  потере контекста языка.
- Длина примеров кода в официальных гайдах Flutter нередко превышает 512 токенов. Правило «fenced code неделим» при
  жёстком лимите max_tokens: 512 приведёт к ошибкам чанкинга.

### 2.4 Корректность embedding spaces, retrieval, reranking и filters

- Изоляция пространств векторов: Решение разделять коллекции по шаблону `flutter__<embedding-slug>-<dims>__<strategy_id>`
  абсолютно корректно и исключает смешивание векторных пространств.
- Асимметрия задач: Модель gemini-embedding-001 требует явного указания task_type: RETRIEVAL_DOCUMENT для чанков и
  RETRIEVAL_QUERY для пользовательских запросов. Voyage AI аналогично требует input_type="document" /
  input_type="query". Архитектура должна закрепить единый параметр задачи в интерфейсе EmbeddingProvider.
- Логика дедупликации: Правило «dedupe по (document_id, section)» ошибочно отбрасывает последующие чанки одной
  секции (например, код, если он вынесен во 2-й чанк секции).
- Поведение при min_score: null: В base.yaml по умолчанию min_score: null. Векторный поиск cosine в Qdrant всегда
  возвращает top_k результатов. Без порога отсечения RAG никогда не перейдёт в статус insufficient_context до вызова
  LLM.

### 2.5 Достаточность схемы evaluation и честность экспериментов

- Разделение на 15 dev и 30 test с доступом к test только по флагу --final полностью защищает от data leakage (N03,
  N04).
- 15 вопросов на dev-выборке дают высокую дисперсию (~6.7% на вопрос); для калибровки порогов схожести это
  допустимо, но требует явного указания в отчёте об исследовании.
- Использование LLM-as-a-Judge на той же модели Gemini создаёт self-preference bias. Для честной оценки требуется
  детерминированный structured output и ручная кросс-валидация выборки ответов.

### 2.6 Границы модулей и отказ внешних API

- Критический дефект Qdrant Embedded: Запуск Qdrant в локальном встроенном режиме (path="./data/index/qdrant")
  использует эксклюзивную файловую блокировку ОС (flock). Одновременный запуск flutter-rag serve (FastAPI) и вызов
  flutter-rag ask / evaluate из другого терминала вызовет немедленный аварийный сбой (Lock failed).
- Завершение фоновых очередей: При вызове CLI отсутствует гарантированный вызов langfuse.flush(), что приведёт к
  потере трейсов при завершении короткоживущих процессов.

### 2.7 Выполнимость на Mac mini M4 и доступных тарифах

- Нагрузка на память и диск минимальна: ~760 файлов (~8 МБ текста) дают ~3000–4000 чанков. Векторный индекс 768-dim
  займёт менее 30 МБ.
- Критический дефект лимитов Gemini Free Tier: Бесплатный тариф Google AI Studio имеет ограничение 1,500 RPD
  (Requests Per Day). Если выполнять эмбеддинг по одному чанку на запрос, индексация 3000 чанков гарантированно
  исчерпает суточную квоту на середине процесса. Обязателен батчинг запросов эмбеддинга (до 50–100 текстов в одном
  запросе).

## 3. Детализированный реестр замечаний

### 3.1 Блокирующие замечания (Blockers)

#### [B1] Отсутствие обязательного батчинга в embeddings приведёт к блокировке по 429 ResourceExhausted

- Файл/раздел: docs/architecture.md §3.1 (пункт 8), lab1/configs/base.yaml
- Доказательство: В корпусе ~761 документ. При секционном чанкинге формируется ~3000–4000 чанков. Лимит Gemini API
  Free Tier для эмбеддингов составляет 1,500 RPD и 15–30 RPM. Поточечная отправка чанков исчерпает суточный лимит за
  15 минут, прервав индексацию.
- Влияние: Срыв этапа 03 и 04 при первой же попытке проиндексировать реальный срез корпуса.
- Минимальное исправление: В спецификацию EmbeddingProvider и реализацию Gemini/Voyage добавить обязательный
  параметр batch_size: int = 50 (Google GenAI SDK поддерживает список строк в embed_content). Индексация 3500 чанков
  займёт 70 запросов вместо 3500.

#### [B2] Монопольная файловая блокировка Qdrant Embedded при параллельной работе

- Файл/раздел: docs/architecture.md §6 (D3), lab1/src/flutter_rag/config.py
- Доказательство: Движок Qdrant Embedded при открытии каталога на диске захватывает эксклюзивный flock. Если
  запущен фоновый сервис flutter-rag serve, любая команда CLI (ask, ingest, evaluate) падает с системной ошибкой
  блокировки базы данных. Аналогично uvicorn --workers 2 упадёт при старте.
- Влияние: Невозможность проводить тестирование API и CLI одновременно; риск повреждения хранилища при некорректном
  завершении процесса.
- Минимальное исправление:
  1. В docs/architecture.md явно зафиксировать ограничение: uvicorn запускается строго с --workers 1.
  2. В модуле vectorstore предусмотреть перехват ошибки захвата локальной БД с понятным сообщением студенту:
     «Локальная база заблокирована другим процессом (например, работающим сервером flutter-rag serve). Остановите
     его или используйте внешнюю БД через QDRANT_URL».

#### [B3] Ошибочные 404-ссылки в источниках из-за внутренних файлов _*.md

- Файл/раздел: docs/architecture.md §1, §4 (SourceDocument.url), lab1/configs/base.yaml
- Доказательство: В репозитории flutter/website в sites/docs/src/content/ находятся файлы с префиксом _ (например,
  sites/docs/src/content/add-to-app/android/_initial-route-cached-engine.md). На сайте https://docs.flutter.dev/add-
  to-app/android/_initial-route-cached-engine отдаётся HTTP 404 (проверено прямым curl-запросом).
- Влияние: RAG выдаёт пользователю недействительные ссылки в поле sources, проваливая требования §13 методички и
  валидацию цитат.
- Минимальное исправление: В configs/base.yaml в правила фильтрации exclude добавить маски:
  `exclude: ["**/_*.md", "**/_includes/**", "sites/docs/src/content/release/release-notes/**"]`. Вспомогательные
  инклуды должны встраиваться в родительские страницы на шаге preprocessing либо исключаться из автономного индекса.

### 3.2 Замечания высокого приоритета (High)

#### [H1] Эффект «сиротских чанков» (Orphan Chunks) при эмбеддинге секций

- Файл/раздел: docs/architecture.md §4 (Chunk.text)
- Доказательство: В спецификации указано: text: str # то, что эмбеддится (с заголовком секции). Во многих
  руководствах Flutter заголовки секций типовые: ## Examples, ## Overview, ## Properties. Без контекста имени
  документа вектор такого чанка теряет семантику (непонятно, пример какого виджета представлен).
- Влияние: Резкое падение Recall@K и Precision@K при поиске по конкретным классам и терминам.
- Минимальное исправление: Текст для эмбеддинга должен формироваться с префиксом контекста документа:
  `f"Page: {doc.title} > {' > '.join(chunk.section_path)}\n\n{chunk.raw_text}"`.

#### [H2] Дедупликация по (document_id, section) удаляет часть кода

- Файл/раздел: docs/architecture.md §3.2 (span filter: dedupe (по document_id+section))
- Доказательство: Если секция документа превышает 512 токенов, чанкер делит её на чанки с одинаковым section_path,
  но разными ordinal (например, чанк 0 — начало кода, чанк 1 — продолжение). Текущее правило дедупликации оставит
  только один чанк и выбросит второй.
- Влияние: Ответ генератора будет содержать обрезанный или синтаксически некорректный код.
- Минимальное исправление: Дедупликацию выполнять либо по точному совпадению хеша содержимого content_hash, либо по
  коэффициенту overlap текста, либо ограничить максимум 2 чанками на секцию с объединением соседних фрагментов при
  сборке контекста.

#### [H3] Зависимость отсечения контекста от неоткалиброванного min_score

- Файл/раздел: docs/architecture.md §3.2, lab1/configs/base.yaml
- Доказательство: В base.yaml установлено min_score: null. Косинусное расстояние в Qdrant всегда возвращает
  заданное количество top_k результатов, даже если запрос абсолютно нерелевантен. Условие если кандидатов нет →
  status=insufficient_context при min_score: null никогда не сработает до LLM.
- Влияние: Нерелевантные чанки будут уходить в LLM, расходуя токены генерации и провоцируя галлюцинации.
- Минимальное исправление: Описать в архитектуре два состояния: при min_score: null отказ выполняется моделью по
  системному промпту; на этапе 05 порог min_score калибруется на dev-выборке под конкретную модель эмбеддингов и
  фиксируется в конфиге.

#### [H4] Риск сбоя чанкера на блоках кода длиннее max_tokens

- Файл/раздел: docs/architecture.md §6 (D10)
- Доказательство: В правиле указано: «fenced code неделим, max_tokens: 512». В руководствах Flutter полные листинги
  StatefulWidget достигают 800–1200 токенов.
- Влияние: Либо чанкер аварийно падает, либо порождает чанк с нарушением лимита токенов, либо выбрасывает блок кода.
- Минимальное исправление: В правиле D10 уточнить: если отдельный блок кода превышает max_tokens, для него
  допускается расширенный порог (soft cap до 1024 токенов), либо чанк разбивается по границам методов/строк с
  сохранением языка подсветки в сигнатуре блока.

#### [H5] Высокая латентность и риск сетевых сбоев при скачивании 760 страниц по отдельности

- Файл/раздел: docs/architecture.md §3.1 (пункт 4)
- Доказательство: Загрузка 760 файлов отдельными HTTP-запросами к raw.githubusercontent.com при задержке 150 мс на
  запрос займёт более 2 минут и может вызвать временный троттлинг со стороны CDN Fastly.
- Влияние: Нестабильность повторных запусков граббера без явных признаков ошибки.
- Минимальное исправление: В граббере реализовать асинхронный пул загрузки (httpx.AsyncClient с
  asyncio.Semaphore(10)) с повторными попытками tenacity, либо альтернативно скачивать архив снапшота
  https://github.com/flutter/website/archive/<sha>.tar.gz и распаковывать только путь sites/docs/src/content.

### 3.3 Замечания среднего приоритета (Medium)

#### [M1] Риск потери трейсов Langfuse при завершении CLI-процессов

- Файл/раздел: docs/architecture.md §6 (D8), lab1/src/flutter_rag/cli.py
- Доказательство: Python SDK Langfuse v5 отправляет события в фоновом потоке батчами. При выходе из функции main()
  интерпретатор завершает фоновые потоки до отправки данных по сети, если не вызван flush().
- Влияние: В UI Langfuse пропадают последние спаны и метрики генерации.
- Минимальное исправление: В точке входа cli.py добавить гарантированный вызов atexit.register(langfuse_client.flush)
  или оборачивать вызовы пайплайна в контекстный менеджер с вызовом flush().

#### [M2] Отсутствие локального кэша для промптов

- Файл/раздел: docs/architecture.md §6 (D9)
- Доказательство: Предлагается брать промпты из Langfuse Prompt Management. При сбоях сети или отсутствии интернета
  система полностью теряет способность отвечать на вопросы.
- Влияние: Нарушение автономности локальной разработки и прогона unit-тестов.
- Минимальное исправление: Промпты v1, v2 хранить как версионируемые текстовые/YAML шаблоны в репозитории
  (lab1/prompts/), а в Langfuse отправлять их метку и хэш. Langfuse Prompt Management использовать как опциональный
  источник.

#### [M3] Несогласованность параметров асимметричного поиска между провайдерами

- Файл/раздел: docs/architecture.md §2 (embeddings)
- Доказательство: В Google GenAI параметр именуется task_type="RETRIEVAL_DOCUMENT" / "RETRIEVAL_QUERY", а в Voyage
  AI — input_type="document" / "query".
- Влияние: Ошибки при переключении моделей в конфиге.
- Минимальное исправление: Протокол EmbeddingProvider должен принимать унифицированный enum EmbeddingTask:
  Literal["document", "query"], а внутренний адаптер каждого провайдера транслирует его в специфичный аргумент SDK.

#### [M4] Отсутствие предварительной валидации ключей в CLI

- Файл/раздел: lab1/src/flutter_rag/cli.py, config.py
- Доказательство: Поля gemini_api_key и др. в Settings объявлены как опциональные (SecretStr | None = None).
- Влияние: При запуске flutter-rag ask ошибка отсутствия ключа возникнет глубоко внутри пайплайна после выполнения
  поиска и фильтрации.
- Минимальное исправление: Добавить валидацию обязательных для конкретной команды ключей на старте выполнения
  cmd_ask, cmd_ingest, cmd_serve с выводом краткой подсказки: «Не задан GEMINI_API_KEY. Заполните его в .env согласно
  docs/SETUP_ACCOUNTS.md».

### 3.4 Замечания низкого приоритета и проектные гипотезы (Low / Hypotheses)

#### [L1] Вопрос соответствия понятию «бесплатная модель» (§7 методички) и локальная альтернатива

- Файл/раздел: docs/requirements.md (Открытый вопрос 2), docs/architecture.md §6 (D5)
- Анализ: Методичка приводит в пример Sentence Transformers, BGE, E5. Хотя квоты Google AI Studio и Voyage
  бесплатны, некоторые преподаватели трактуют этот пункт как «локальная открытая модель без внешних API».
- Гипотеза/Решение: В качестве запасного варианта для embedding model #2 не обязательно ставить тяжеловесный
  PyTorch (torch весит ~800 МБ). Отличная альтернатива — библиотека fastembed (от создателей Qdrant) с моделью
  BAAI/bge-small-en-v1.5. Она работает на легковесном ONNX Runtime, нативно оптимизирована под Apple Silicon и не
  требует внешних API-ключей.

#### [L2] Порядок чанков при формировании контекста (build_context)

- Файл/раздел: docs/architecture.md §3.2
- Анализ: Если передавать в LLM 5 чанков, отсортированных исключительно по скору релевантности, нарушается
  естественный порядок изложения документа (фрагмент снизу страницы окажется выше фрагмента сверху).
- Рекомендация: Если в топ-5 попало несколько чанков из одного и того же документа, группировать их и упорядочивать
  по ordinal.

#### [L3] Защита от смещения при LLM-as-a-Judge

- Файл/раздел: docs/RESEARCH_PLAN.md §10
